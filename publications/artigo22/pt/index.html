Resumo

Este artigo apresenta uma explicação técnica, formal e didática do processo de inferência em modelos de linguagem baseados em Transformers, desde a tokenização da entrada até a seleção do próximo token. A exposição combina fórmulas, exemplos numéricos reproduzíveis e seis figuras para mostrar embeddings, codificação posicional, self-attention, máscaras, conexões residuais, normalização, redes feed-forward, logits, softmax e estratégias de decodificação. O estudo de caso da palavra ambígua “banco” demonstra, em escala reduzida, como o contexto altera representações sem pretender reproduzir o comportamento de um modelo treinado real. Por fim, o texto distingue a inferência do modelo da execução governada de um sistema agentivo e apresenta uma interpretação pública e não normativa de suas implicações para o SGAEIA.

Palavras-chave: AI; Transformer; inferência; LLM; atenção; tokenização; embeddings; softmax; propriedades emergentes; SGAEIA.

1. Introdução e escopo

Função desta seção. Fixa o objetivo, as convenções e os limites do texto antes de qualquer técnica. É necessária porque os números e as figuras que seguem são didáticos; sem este aviso, poderiam ser lidos como medições de um modelo real.

Este documento descreve, etapa por etapa, o que ocorre dentro de um modelo de linguagem baseado na arquitetura Transformer (Vaswani et al., 2017), desde o texto de entrada até o token de saída, usando como fio condutor a frase ambígua "O banco estava lotado". O objetivo é tornar a "caixa-preta" inteligível: cada etapa traz o conceito, o mecanismo matemático, a técnica adotada, um exemplo numérico e as referências que a sustentam.

Convenções. Referências no texto seguem o formato (Autor, ano) e estão listadas na seção 18. Termos técnicos aparecem em negrito na primeira ocorrência e estão definidos no Glossário (seção 17). Matrizes são escritas em maiúsculas (Q, K, V) e dimensões como n (tamanho da sequência), d_model (dimensão do modelo) e d_k (dimensão de cada cabeça).

Aviso sobre os exemplos numéricos. Os números das seções 3 a 11 foram calculados por código (Python/NumPy) com dimensões reduzidas e vetores escolhidos à mão para fins didáticos. Em modelos reais, os pesos são aprendidos e as dimensões são muito maiores (por exemplo, d_model = 512 no Transformer original e 768 no BERT-base).

Escopo. O texto descreve o Transformer em termos gerais (variantes codificador, decodificador e codificador-decodificador).

2. Visão geral do fluxo

Por que o fluxo tem estas etapas, nesta ordem. Cada etapa resolve um problema que a anterior deixa em aberto. A rede só opera sobre números (tokenização); números inteiros não têm geometria nem ordem (embeddings e posição); cada token precisa de contexto (atenção); a mistura contextual precisa ser transformada, estabilizada e repetida em profundidade (FFN, Add & Norm, empilhamento); o comportamento depende de pesos que precisam ser aprendidos (treino); e o resultado final precisa virar uma palavra (logits, softmax e decodificação). A tabela resume o problema que cada etapa resolve e o que faltaria sem ela.

Etapa Problema que resolve Sem ela
Tokenização A rede só processa números, e o vocabulário precisa ser finito Não há entrada numérica; palavras raras ficariam sem representação ou as sequências ficariam longas demais
Embedding IDs inteiros são rótulos arbitrários, sem noção de similaridade Cada token seria um vetor one-hot com uma dimensão por token do vocabulário (dezenas de milhares), esparso e sem similaridade entre tokens
Codificação posicional A atenção, por construção, não usa a ordem das palavras Atenção sem máscara não distingue ordens diferentes das mesmas palavras (Vaswani et al., 2017)
Self-attention Cada token precisa de informação dos demais Cada token seria interpretado isoladamente; "banco" teria sempre o mesmo vetor
Multi-head Várias relações precisam ser captadas ao mesmo tempo Uma única média ponderada por camada, que inibe atender a subespaços de representação distintos (Vaswani et al., 2017)
Add & Norm Sinal e gradiente precisam atravessar muitas camadas Treino instável ou degradado em pilhas profundas (He et al., 2016; Ba et al., 2016; Xiong et al., 2020)
FFN A atenção apenas combina Values; falta transformação por token Sem a parte da camada que concentra cerca de dois terços dos parâmetros (Geva et al., 2021)
Empilhamento Relações complexas exigem composição em passos Só relações diretas em um passo; certos circuitos exigem duas ou mais camadas (Elhage et al., 2021; Olsson et al., 2022)
Treino Pesos aleatórios não produzem linguagem Um circuito sem comportamento útil, como nos exemplos com pesos aleatórios
Saída Um vetor de números precisa virar um token Sem logits, softmax e decodificação não há distribuição nem palavra escolhida

A inferência em um modelo de linguagem é a execução do modelo já treinado, com pesos fixos, para produzir uma saída a partir de uma entrada. No caso de um modelo gerador, essa execução é um ciclo: o modelo calcula uma distribuição de probabilidade sobre o próximo token, um token é escolhido, anexado à entrada, e o ciclo se repete (geração autorregressiva). A computação de uma passagem completa pelas camadas chama-se forward pass (propagação direta).

A arquitetura original combina um codificador e um decodificador (Vaswani et al., 2017). Duas famílias derivadas dominam o uso atual: modelos somente codificador, como o BERT (Devlin et al., 2019), que veem a sequência nos dois sentidos, e modelos somente decodificador, como a série GPT (Radford et al., 2018; Radford et al., 2019; Brown et al., 2020), que geram texto da esquerda para a direita. Os mecanismos descritos nas próximas seções valem para todas, com a diferença principal na máscara de atenção (seção 6).

Etapa Operação Técnica principal Referência-chave
1. Tokenização Texto → IDs inteiros BPE, SentencePiece Sennrich et al., 2016; Kudo e Richardson, 2018
2. Embedding e posição IDs → vetores + ordem Matriz de embeddings; senoidal ou RoPE Mikolov et al., 2013; Vaswani et al., 2017; Su et al., 2021
3. Self-attention Mistura contextual entre tokens Produto escalar escalonado e softmax Bahdanau et al., 2015; Vaswani et al., 2017
4. Multi-head Várias relações em paralelo Subespaços de dimensão d_k Vaswani et al., 2017; Voita et al., 2019
5. Add & Norm Estabilidade do sinal Conexão residual; LayerNorm, RMSNorm He et al., 2016; Ba et al., 2016; Zhang e Sennrich, 2019
6. FFN Transformação não linear por posição MLP com ReLU, GELU ou SwiGLU Geva et al., 2021; Shazeer, 2020
7. Empilhamento Refinamento em profundidade N camadas Tenney et al., 2019
8. Saída Logits → probabilidades → token Softmax, temperatura, top-k, top-p Holtzman et al., 2020

O treinamento (seção 10) é a etapa que define os pesos. A inferência apenas os utiliza.

3. Etapa 1 – Entrada e tokenização

Por que esta etapa é necessária. Computadores aplicam operações aritméticas a números; sem converter o texto em IDs, não há entrada para a rede. O vocabulário precisa ser finito e fixo porque a camada de saída tem uma dimensão por token (seção 11). A escolha por subpalavras resolve um compromisso real: palavras inteiras deixam termos novos sem representação, e caracteres isolados geram sequências longas, o que encarece a atenção, cujo custo cresce com o quadrado do comprimento (seção 5; Sennrich et al., 2016).

Conceito. Redes neurais operam sobre números, não sobre texto. A tokenização converte a cadeia de caracteres em uma sequência de tokens (unidades do vocabulário) e cada token em um ID inteiro. O vocabulário é um conjunto finito, fixado antes do treinamento, tipicamente de dezenas de milhares de entradas.

Por que subpalavras. Vocabulários de palavras inteiras não representam palavras raras ou novas (problema das palavras fora do vocabulário, ou OOV), e vocabulários de caracteres geram sequências longas demais. As unidades de subpalavra equilibram os dois extremos: palavras frequentes viram um token, e palavras raras são decompostas em pedaços reutilizáveis (Sennrich et al., 2016).

Técnicas adotadas.

  • BPE (Byte Pair Encoding): parte de caracteres e funde, iterativamente, o par adjacente mais frequente em um novo símbolo. Foi proposto como algoritmo de compressão por Gage (1994) e adaptado à tradução automática por Sennrich et al. (2016). A variante em nível de bytes é usada em modelos da série GPT (Radford et al., 2019).
  • WordPiece: escolhe as fusões pelo ganho de verossimilhança do modelo de linguagem, em vez da simples frequência (Schuster e Nakajima, 2012; Wu et al., 2016). É usada no BERT (Devlin et al., 2019).
  • Unigram LM e SentencePiece: o Unigram parte de um vocabulário grande e poda o que contribui menos (Kudo, 2018). O SentencePiece implementa BPE e Unigram diretamente sobre o texto bruto, sem pré-tokenização por espaços, o que o torna independente de idioma (Kudo e Richardson, 2018).

Exemplo numérico (BPE em corpus didático). Corpus com a frequência de cada palavra, onde </w> marca o fim de palavra: low (5), lower (2), newest (6), widest (3). Início: cada palavra é uma sequência de caracteres. Em cada passo, funde-se o par mais frequente (empates resolvidos pela ordem de ocorrência). Resultado calculado por código:

Passo Par fundido Frequência do par Novo símbolo

Aplicação à frase-guia. Em um vocabulário real, "O banco estava lotado" costuma gerar poucos tokens por palavra, pois são palavras comuns do português. Para os fins deste documento, adota-se a simplificação 4 palavras = 4 tokens: [O] [banco] [estava] [lotado], com IDs inteiros ilustrativos (por exemplo, 12, 4871, 905, 23019; os valores reais dependem do tokenizador). Observe que o ID de "banco" é o mesmo nos dois sentidos da palavra: a tokenização não desambigua. A distinção só surgirá nas camadas de atenção (seção 12).

4. Etapa 2 – Embeddings e codificação posicional

Por que esta etapa é necessária. Um ID inteiro é um rótulo arbitrário: o ID 4871 não é "mais parecido" com o 4872 em significado. O embedding converte cada rótulo em um vetor no qual o treino pode organizar similaridade (Bengio et al., 2003; Mikolov et al., 2013), e as operações seguintes (somas, produtos escalares) só fazem sentido sobre vetores. A codificação posicional é necessária porque a atenção, por construção, não usa a ordem: "o gato come o peixe" e "o peixe come o gato" têm os mesmos tokens, e sem informação de posição a atenção sem máscara os trata de forma equivalente a menos de permutação (Vaswani et al., 2017). Em decodificadores com máscara causal, parte da posição pode ser inferida pelo número de tokens visíveis, mas a codificação explícita é a prática padrão.

Embedding. Cada ID seleciona uma linha de uma matriz de pesos W_E de dimensão |V| × d_model, produzindo um vetor denso que representa o token. A ideia de representar palavras como vetores contínuos, em que proximidade geométrica reflete similaridade de uso, vem dos modelos neurais de linguagem (Bengio et al., 2003) e do word2vec (Mikolov et al., 2013). No Transformer, a matriz é aprendida em conjunto com o resto do modelo, os vetores são multiplicados por √d_model e a mesma matriz costuma ser compartilhada com a projeção de saída (Vaswani et al., 2017; Press e Wolf, 2017). Um ponto central: o embedding de entrada é estático, ou seja, "banco" recebe o mesmo vetor em qualquer frase. A contextualização acontece depois, na atenção.

Codificação posicional. A atenção, por si só, trata a entrada como um conjunto: embaralhar os tokens embaralha a saída da mesma forma, sem distinguir ordem. Por isso se soma ao embedding um vetor que depende da posição. A proposta original usa funções senoidais de frequências geométricas (Vaswani et al., 2017):

$$PE_{(pos,,2i)} = \sin!\left(\frac{pos}{10000^{2i/d_{model}}}\right), \qquad PE_{(pos,,2i+1)} = \cos!\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

Cada par de dimensões oscila em uma frequência diferente, e a diferença entre posições pode ser expressa como transformação linear dos vetores, o que facilita ao modelo aprender relações de distância relativa (Vaswani et al., 2017).

Alternativas adotadas na literatura.

  • Posições aprendidas: uma tabela treinável, usada no BERT e no GPT-2 (Devlin et al., 2019; Radford et al., 2019).
  • Posições relativas: a atenção passa a depender da distância entre tokens (Shaw et al., 2018).
  • RoPE (rotary embeddings): rotaciona Q e K conforme a posição, codificando posição relativa no próprio produto escalar (Su et al., 2021). É usada em modelos como o LLaMA (Touvron et al., 2023).
  • ALiBi: adiciona um viés linear por distância aos scores de atenção, melhorando a extrapolação para sequências mais longas que as do treino (Press et al., 2022).

Exemplo numérico. Com d_model = 4 (didático; o Transformer original usa 512), embeddings escolhidos à mão para os quatro tokens e a codificação senoidal calculada pela fórmula acima. Para "banco" (posição 1): PE = [sen(1), cos(1), sen(0,01), cos(0,01)] = [0,841; 0,540; 0,010; 1,000]. Somando ao embedding [0; 1; 0,5; 0] obtém-se x = [0,841; 1,540; 0,510; 1,000]. 5. Etapa 3 – Self-attention (autoatenção)

Por que esta etapa é necessária. O sentido de uma palavra depende dos vizinhos, e o embedding de entrada é estático (seção 4): "banco" começa igual em qualquer frase. É preciso um mecanismo em que cada token consulte os demais, com pesos que dependam do conteúdo, e não de posições fixas. Modelos recorrentes passam a informação passo a passo, de modo que dependências distantes atravessam muitas operações; na atenção, quaisquer duas posições se ligam em um passo, e o cálculo é paralelizável (Vaswani et al., 2017). A separação em Query, Key e Value é uma escolha de projeto: desacopla o que o token procura, o que ele oferece para ser encontrado e o conteúdo que ele repassa. A divisão por √d_k é necessária para evitar que o softmax sature quando d_k é grande.

Conceito. A self-attention permite que cada token recalcule sua representação como uma média ponderada das representações de todos os tokens da sequência (incluindo ele mesmo), com pesos que dependem do conteúdo. O mecanismo de atenção surgiu na tradução automática, para alinhar palavras de saída a palavras de entrada (Bahdanau et al., 2015), e o Transformer o generalizou para operar da sequência sobre ela mesma (Vaswani et al., 2017).

Três papéis por token. Três matrizes de pesos treináveis projetam cada vetor de entrada:

  • Query (Q = X·Wq): o que este token procura.
  • Key (K = X·Wk): o que este token oferece para ser encontrado.
  • Value (V = X·Wv): o conteúdo que este token repassa se for selecionado.

Fórmula (produto escalar escalonado).

$$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V$$

  • QKᵀ mede a compatibilidade entre cada Query e cada Key (produto escalar: valor alto quando os vetores apontam na mesma direção).
  • Divisão por √d_k: se as componentes de q e k têm média 0 e variância 1, o produto escalar tem variância d_k. Sem a divisão, os scores crescem com a dimensão e empurram o softmax para regiões de gradiente quase nulo (Vaswani et al., 2017).
  • Softmax: converte cada linha de scores em pesos positivos que somam 1.
  • Multiplicação por V: o resultado é a média dos Values ponderada por esses pesos, o token contextualizado.

Exemplo numérico (d_model = 4, d_k = 2, valores calculados por código). Usando X da seção 4 e matrizes Wq, Wk, Wv escolhidas à mão, obtém-se, para o token "banco" (posição 1):

Passo O banco estava lotado
Score q·k (QKᵀ) 4,476 6,130 5,353 4,375
Score / √2 3,165 4,334 3,785 3,093
Peso (softmax) 0,143 0,459 0,265 0,133

Os pesos somam 1,000. A saída para "banco" é Z = 0,143·v_O + 0,459·v_banco + 0,265·v_estava + 0,133·v_lotado = [1,043; 1,360], onde v_O = [1,000; 1,500], v_banco = [1,096; 2,040], v_estava = [1,419; 0,384] e v_lotado = [0,156; 0,810]. O vetor de "banco" deixou de ser só "banco": incorporou, em proporção, informação dos demais tokens. Como os pesos deste exemplo foram escolhidos à mão, não se deve ler significado linguístico no padrão obtido; em um modelo treinado, são os próprios Wq, Wk e Wv que aprendem quais relações importam.

Como ler o mapa (Figura 4). Linhas são as Queries (quem pergunta); colunas são as Keys (para quem olha); cada linha soma 1. À esquerda, todos os tokens veem todos (estilo codificador). À direita, a máscara causal zera as posições futuras (seção 6).

Custo. A matriz de scores tem n × n entradas, então tempo e memória crescem quadraticamente com o comprimento da sequência. Implementações como o FlashAttention reduzem o tráfego de memória sem alterar o resultado matemático (Dao et al., 2022).

6. Etapa 4 – Multi-head attention e máscaras

Por que esta etapa é necessária. Uma única atenção produz uma só média ponderada por token, o que, segundo Vaswani et al. (2017), inibe atender ao mesmo tempo a informações de subespaços de representação diferentes. Várias cabeças permitem relações distintas em paralelo sem aumentar o custo total, pois cada cabeça trabalha em dimensão menor. A máscara causal é necessária para a geração: no treino todo o texto está disponível, e sem a máscara o modelo "veria" o token que deve prever, aprendendo a copiá-lo e falhando na inferência, em que o futuro não existe. A máscara de preenchimento evita que posições vazias influenciem o resultado. As variantes de K e V compartilhados e o KV cache existem porque, na geração, reler e recalcular todo o passado a cada token seria proibitivo (Pope et al., 2023).

Conceito. Uma única atenção produz uma só média ponderada por token. A multi-head attention executa h atenções em paralelo, cada uma com suas próprias matrizes Wq, Wk, Wv e operando em um subespaço de dimensão d_k = d_model / h. As saídas das cabeças são concatenadas e projetadas por uma matriz Wo (Vaswani et al., 2017):

$$\mathrm{MultiHead}(X) = \mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h),W^{O}, \qquad \mathrm{head}_i = \mathrm{Attention}(XW^{Q}_i,,XW^{K}_i,,XW^{V}_i)$$

Exemplo numérico (Transformer original, versão base). Com d_model = 512 e h = 8, cada cabeça tem d_k = d_v = 64, e o custo computacional total é semelhante ao de uma única cabeça de dimensão 512 (Vaswani et al., 2017). As quatro matrizes de projeção de uma camada de atenção têm, juntas, 4 × 512 × 512 = 1.048.576 pesos (sem contar vieses). Observação de coerência: h deve dividir d_model; por isso 12 cabeças não se aplicam a d_model = 512 (o BERT-base usa 12 cabeças com d_model = 768, ou seja, d_k = 64; Devlin et al., 2019).

Por que várias cabeças. Cada cabeça pode aprender um tipo de relação. Estudos de análise de atenção no BERT encontraram cabeças que se concentram em delimitadores, em deslocamentos posicionais fixos e em relações sintáticas como a de verbo e objeto direto (Clark et al., 2019). Há também evidência de que muitas cabeças são redundantes: um subconjunto pequeno responde pela maior parte do desempenho, e as demais podem ser podadas com pouca perda (Voita et al., 2019; Michel et al., 2019).

Variantes para inferência eficiente. Em Multi-Query Attention todas as cabeças compartilham um único par de matrizes K e V (Shazeer, 2019). Em Grouped-Query Attention, grupos de cabeças compartilham K e V, em um meio-termo entre qualidade e memória (Ainslie et al., 2023). Ambas reduzem o tamanho do KV cache, o armazenamento dos K e V já calculados que evita recomputar o passado a cada novo token gerado (Pope et al., 2023).

Máscaras de atenção.

  • Bidirecional (codificador): cada posição vê todas as outras. É o regime do BERT (Devlin et al., 2019).
  • Causal (decodificador): antes do softmax, os scores das posições futuras recebem −∞, e seus pesos tornam-se exatamente 0. Isso preserva a propriedade autorregressiva: a previsão da posição t depende apenas das posições até t (Vaswani et al., 2017; Radford et al., 2019).
  • De preenchimento (padding): ignora posições vazias usadas para igualar o tamanho dos lotes.

Exemplo numérico da máscara causal. Na linha de "banco", os scores escalonados eram [3,165; 4,334; 3,785; 3,093]. Com máscara causal, as duas últimas posições ("estava" e "lotado", futuras) viram −∞, e o softmax sobre [3,165; 4,334] resulta em [0,237; 0,763; 0; 0]. Portanto, em um modelo gerador, "banco" não pode olhar para "lotado"; a desambiguação por palavras posteriores só ocorre quando elas já foram lidas, ou seja, nas posições seguintes. Em modelos bidirecionais, como o da Figura 4, o olhar para a frente é permitido.

7. Etapa 5 – Conexão residual e normalização (Add & Norm)

Por que esta etapa é necessária. Empilhar muitas camadas obriga o sinal, e o gradiente no treino, a atravessar muitas transformações. Sem um atalho, redes mais profundas passam a ter desempenho pior no treino, o chamado problema de degradação, que a conexão residual mitiga (He et al., 2016). A residual também preserva a informação original e deixa cada subcamada aprender apenas uma correção. A normalização mantém a escala dos valores estável ao longo da profundidade (Ba et al., 2016), e sua posição (Pré-LN ou Post-LN) afeta a estabilidade do treino sem aquecimento cuidadoso (Xiong et al., 2020). Sem essas etapas, a profundidade que dá capacidade ao modelo não seria treinável de forma confiável.

Conexão residual. Depois de cada subcamada (atenção ou FFN), a entrada da subcamada é somada à sua saída: y = x + Subcamada(x). A ideia vem das redes residuais da visão computacional (He et al., 2016). Ela cria um caminho direto para o sinal e para o gradiente, o que viabiliza o treinamento de pilhas profundas, e faz cada subcamada aprender uma correção ao que já existe, em vez de reconstruir tudo. Na interpretação de circuitos, esse caminho é o fluxo residual, um canal que todas as camadas leem e no qual escrevem (Elhage et al., 2021).

Normalização. Sem controle de escala, os valores podem crescer ou encolher ao longo das camadas e desestabilizar o treino. A LayerNorm normaliza cada token separadamente, ao longo de suas d_model componentes (e não ao longo do lote), e depois aplica uma escala γ e um deslocamento β aprendidos (Ba et al., 2016):

$$\mathrm{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^{2} + \epsilon}} + \beta, \qquad \mu = \tfrac{1}{d}\sum_i x_i, \quad \sigma^{2} = \tfrac{1}{d}\sum_i (x_i - \mu)^2$$

A RMSNorm omite a subtração da média e normaliza apenas pela raiz do valor quadrático médio, com custo menor e desempenho comparável (Zhang e Sennrich, 2019); é adotada em modelos como o LLaMA (Touvron et al., 2023).

Pós-LN e Pré-LN. O Transformer original aplica a normalização depois da soma residual (Post-LN). Muitos modelos atuais a aplicam antes de cada subcamada (Pré-LN), variante que treina de forma mais estável e dispensa o aquecimento (warm-up) cuidadoso da taxa de aprendizado (Xiong et al., 2020).

Exemplo numérico (token "banco", versão causal, γ = 1, β = 0). A saída da atenção projetada por Wo é o = [1,074; 1,912; 0,537; 0,956]. A entrada era x = [0,841; 1,540; 0,510; 1,000]. Soma residual: r = x + o = [1,915; 3,453; 1,047; 1,956]. Média μ = 2,093 e variância σ² = 0,748. LayerNorm (ε = 10⁻⁵): [(1,915 − 2,093)/0,865; …] = [−0,205; 1,572; −1,209; −0,158], com média 0 e variância 1. Para comparação, a RMSNorm do mesmo vetor, com raiz do quadrático médio 2,264, dá [0,846; 1,525; 0,462; 0,864]: mantém a proporção entre componentes, sem centralizar em zero.

8. Etapa 6 – Rede feed-forward (FFN)

Por que esta etapa é necessária. Na atenção, os pesos dependem do conteúdo, mas a saída é uma média ponderada de Values obtidos por projeções lineares (V = X·Wv, e depois Wo); a única não linearidade ali está no softmax, que decide os pesos. A FFN acrescenta uma transformação não linear aplicada a cada token, depois que a informação de contexto foi reunida. Há também uma razão de capacidade: as FFNs concentram cerca de dois terços dos parâmetros de um Transformer e funcionam como memórias de padrões (Geva et al., 2021). A expansão para d_ff = 4 × d_model no modelo original é uma escolha de projeto que aumenta essa capacidade (Vaswani et al., 2017).

Conceito. Após a atenção, cada posição passa por uma pequena rede neural de duas camadas lineares com uma não linearidade no meio, aplicada independentemente a cada token e com os mesmos pesos para todas as posições da camada (Vaswani et al., 2017):

$$\mathrm{FFN}(x) = \max(0,; xW_1 + b_1),W_2 + b_2$$

A atenção mistura informação entre tokens. A FFN transforma a informação dentro de cada token, expandindo-a para uma dimensão maior d_ff (no original, 2048, ou seja, 4 × d_model), aplicando a não linearidade e comprimindo de volta a d_model.

Funções de ativação adotadas. ReLU no Transformer original; GELU no BERT e no GPT (Hendrycks e Gimpel, 2016; Devlin et al., 2019; Radford et al., 2019); variantes com porta (GLU), como a SwiGLU, em modelos recentes (Shazeer, 2020; Touvron et al., 2023).

Interpretação. Geva et al. (2021) propõem que a FFN funciona como uma memória chave-valor: as colunas de W1 detectam padrões no vetor de entrada (chaves), e as linhas de W2 contribuem com informação associada (valores). Essa leitura ajuda a explicar por que boa parte do conhecimento factual parece residir nas FFNs, e não na atenção. Trata-se de uma hipótese interpretativa sustentada por análise empírica, e não de um fato demonstrado em todos os modelos.

Exemplo numérico de parâmetros (Transformer base). W1 tem 512 × 2048 = 1.048.576 pesos e W2 tem 2048 × 512 = 1.048.576, total de 2.097.152 por camada (sem vieses). Somando os 1.048.576 da atenção (seção 6), a camada tem cerca de 3,15 milhões de pesos, dos quais a FFN responde por cerca de dois terços.

Exemplo numérico de cálculo (d_model = 4, d_ff = 8; W1 e W2 gerados aleatoriamente com semente fixa, sem treino). Para o token "estava" (posição 2), a entrada da FFN é o vetor normalizado [1,389; −0,901; −0,999; 0,511]. Após W1 e ReLU, a camada oculta é [0,907; 0,660; 0,330; 0; 0,623; 0; 1,541; 0,759]: seis das oito unidades ficaram ativas e duas foram zeradas pela ReLU. Após W2, a saída é [0,231; 0,954; 0,437; −0,291]. Somando à entrada (residual) e normalizando, obtém-se [1,613; −0,351; −1,121; −0,141]. Já para "banco" (posição 1), todas as oito unidades ocultas ficaram em zero neste exemplo, logo a saída da FFN é zero e o vetor atravessa a subcamada inalterado pelo caminho residual. Em um modelo treinado, o padrão de ativação esparso é aprendido, e cada token ativa um subconjunto diferente de unidades.

9. Etapa 7 – Empilhamento multicamadas

Por que esta etapa é necessária. Uma camada capta relações em um passo. Muitas tarefas exigem composição: identificar o token, relacioná-lo ao contexto, inferir o sentido e só então prever. O empilhamento permite esse refinamento sucessivo, e as análises de sondagem mostram níveis de informação distintos ao longo das camadas (Jawahar et al., 2019; Tenney et al., 2019; Belrose et al., 2023). Alguns mecanismos documentados exigem ao menos duas camadas de atenção, como os induction heads (Elhage et al., 2021; Olsson et al., 2022). Mais camadas aumentam a capacidade, mas também o custo; por isso o número de camadas é uma escolha de projeto, como mostra a tabela abaixo.

Mecanismo. Um bloco Transformer é a sequência atenção → Add & Norm → FFN → Add & Norm. O modelo empilha N blocos: a saída da camada l é a entrada da camada l + 1, e cada camada tem seus próprios pesos. A matriz de tamanho n × d_model mantém a mesma forma ao longo de toda a pilha; o que muda é o conteúdo de cada vetor, que vai sendo refinado.

Modelo Camadas d_model Cabeças Parâmetros Fonte
Transformer base (original) 6 + 6 512 8 65 milhões Vaswani et al., 2017
BERT-base 12 768 12 110 milhões Devlin et al., 2019
BERT-large 24 1024 16 340 milhões Devlin et al., 2019
GPT-3 (maior versão) 96 12288 96 175 bilhões Brown et al., 2020

O que cada profundidade tende a representar. Estudos de sondagem (probing) no BERT indicam uma divisão aproximada: camadas iniciais captam padrões superficiais e de ordem local; camadas intermediárias, estrutura sintática; camadas mais altas, relações semânticas e de longo alcance (Jawahar et al., 2019). Tenney et al. (2019) observaram que as etapas do pipeline clássico de PLN (classes gramaticais, análise sintática, entidades, papéis semânticos, correferência) são recuperáveis nessa ordem ao longo das camadas. A Figura 5 resume essa tendência.

Refinamento iterativo da previsão. Técnicas como a logit lens e a tuned lens projetam o estado intermediário de cada camada sobre o vocabulário e mostram que a distribuição prevista para o próximo token vai se tornando mais precisa camada após camada (Belrose et al., 2023).

Circuitos que exigem profundidade. Os induction heads (cabeças de indução) são um exemplo documentado: uma cabeça na camada anterior copia informação do token anterior, e uma cabeça posterior a usa para localizar ocorrências passadas de um padrão e prever a sua continuação. Esse mecanismo requer ao menos duas camadas de atenção e foi associado ao surgimento de in-context learning durante o treino (Elhage et al., 2021; Olsson et al., 2022).

Ressalva. As fronteiras por camada variam conforme o modelo, a tarefa e o método de análise. Os intervalos de camadas usados em divulgações didáticas (por exemplo, "a camada 6 resolve o sentido de banco") são ilustrações, e não resultados medidos neste documento.

10. Etapa 8 – Pesos: o que são e como são aprendidos

Por que esta etapa é necessária. Com pesos aleatórios, as etapas anteriores produzem saídas sem relação com a linguagem, como nos exemplos numéricos deste documento. O treino é o que transforma a arquitetura em um modelo útil. A previsão do próximo token é um objetivo adequado porque fornece sinal de aprendizado em qualquer texto, sem rótulos humanos. A retropropagação é necessária porque milhões a bilhões de parâmetros só podem ser ajustados com gradientes calculados de modo eficiente (Rumelhart et al., 1986), e o otimizador, o aquecimento e a regularização existem para que esse ajuste seja estável (Kingma e Ba, 2015; Loshchilov e Hutter, 2019; Vaswani et al., 2017). Esta etapa também justifica a inferência com pesos fixos: o que o modelo "sabe" já foi gravado nos pesos.

O que são os pesos. Os pesos (ou parâmetros) são os números ajustáveis do modelo: a matriz de embeddings; em cada camada, Wq, Wk, Wv, Wo, W1, W2, vieses e os γ e β da normalização; e a projeção final para o vocabulário. Durante a inferência eles são fixos. Todo o "conhecimento" do modelo está nesses valores.

Objetivo de treinamento. Modelos geradores são treinados para prever o próximo token. Dada a sequência x₁…x_T, minimiza-se a entropia cruzada média entre a distribuição prevista e o token que de fato veio a seguir:

$$\mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta!\left(x_t \mid x_{<t}\right), \qquad \mathrm{PPL} = e^{\mathcal{L}}$$

O BERT usa um objetivo diferente, a predição de tokens mascarados (masked language modeling), em que se escondem alguns tokens e o modelo os reconstrói olhando para os dois lados (Devlin et al., 2019). Em ambos os casos não há rótulo humano de significado: o sinal é o próprio texto. Isso é o que fundamenta a ideia de que a desambiguação é uma estratégia emergente para reduzir o erro de predição (seção 13).

Exemplo numérico. Na saída calculada da seção 11 (pesos aleatórios), a probabilidade atribuída a "lotado" é p = 0,022 e a atribuída a "cheio" é 0,623. Se o token correto fosse "lotado", a perda seria −ln(0,022) = 3,806; se fosse "cheio", −ln(0,623) = 0,473. O gradiente da perda em relação aos logits é simplesmente p − y, onde y é o vetor one-hot do token correto: para o alvo "lotado", [−0,978; 0,114; 0,623; 0,094; 0,147], ou seja, o treino empurra o logit de "lotado" para cima e os dos demais para baixo, proporcionalmente ao erro.

Retropropagação e otimização. O gradiente é propagado de volta por todas as camadas pela regra da cadeia, algoritmo conhecido como backpropagation (Rumelhart et al., 1986), e os pesos são atualizados por um otimizador. O Transformer original usou o Adam (Kingma e Ba, 2015) com taxa de aprendizado que cresce linearmente durante um período de aquecimento e depois decai, além de dropout e label smoothing (Vaswani et al., 2017). A variante AdamW, que desacopla a regularização por decaimento de pesos do passo adaptativo, é a escolha comum em modelos atuais (Loshchilov e Hutter, 2019).

Paralelismo no treino e sequência na inferência. No treino, com a máscara causal, todas as posições são calculadas ao mesmo tempo (o texto correto já é conhecido). Na inferência, o token t + 1 depende do token t escolhido, então a geração é sequencial, e o KV cache (seção 6) evita refazer o passado.

Fases de treinamento. Uma prática comum é o pré-treinamento em grande volume de texto bruto, seguido de ajustes para uso específico: fine-tuning supervisionado e alinhamento com preferências humanas, como na abordagem de aprendizado por reforço com feedback humano (Ouyang et al., 2022).

Escala. A perda de modelos de linguagem cai de forma regular, segundo leis de potência, com o aumento de parâmetros, dados e computação (Kaplan et al., 2020). Hoffmann et al. (2022) mostraram que, para um orçamento de computação fixo, parâmetros e volume de dados devem crescer em proporção, e que muitos modelos grandes estavam subtreinados em dados.

11. Etapa 9 – Saída: logits, softmax e decodificação

Por que esta etapa é necessária. A última camada entrega um vetor de d_model números, e o usuário precisa de um token. Os logits mapeiam esse vetor para uma pontuação por token do vocabulário. O softmax os converte em uma distribuição válida (positiva, somando 1), indispensável para a perda de entropia cruzada no treino e para sortear ou escolher o token na inferência. A temperatura e as regras de decodificação são necessárias porque escolher sempre o token mais provável tende a produzir texto repetitivo e degenerado, enquanto sortear sem restrição inclui tokens improváveis; as estratégias top-k e top-p equilibram esses extremos (Holtzman et al., 2020).

Logits. O vetor da última camada na posição atual (h_final, de dimensão d_model) é multiplicado por uma matriz de saída W_out de dimensão d_model × |V|. O resultado são os logits: um número real, sem limites, para cada token do vocabulário. Em muitos modelos, W_out é a transposta da matriz de embeddings (weight tying; Press e Wolf, 2017; Vaswani et al., 2017).

Softmax e temperatura. O softmax converte logits em probabilidades que somam 1. A temperatura T divide os logits antes do softmax: T < 1 concentra a probabilidade nos tokens mais prováveis (saída mais determinística), e T > 1 a espalha (saída mais variada). O uso de temperatura no softmax foi popularizado na destilação de modelos (Hinton et al., 2015).

$$p_i = \frac{e^{z_i / T}}{\sum_{j} e^{z_j / T}}$$

Exemplo numérico. Vocabulário didático de cinco tokens e logits calculados a partir do vetor da posição "estava" (pesos de saída aleatórios, sem treino): lotado −0,818; vazio 0,815; cheio 2,516; aberto 0,626; verde 1,070. Com T = 1, o softmax dá lotado 0,022; vazio 0,114; cheio 0,623; aberto 0,094; verde 0,147 (soma 1,000). Com T = 0,5, "cheio" sobe para 0,899; com T = 2, cai para 0,402 e a distribuição se achata (Figura 6). Em um modelo treinado, esses pesos teriam sido ajustados para que palavras plausíveis após "O banco estava", como "lotado", recebessem probabilidade alta; aqui o exemplo serve apenas para mostrar a aritmética.

Estratégias de decodificação. A escolha do token a partir da distribuição é uma etapa separada do modelo:

  • Gulosa (greedy): escolhe sempre o token de maior probabilidade. No exemplo: "cheio".
  • Amostragem: sorteia o token conforme as probabilidades.
  • Top-k: restringe o sorteio aos k tokens mais prováveis e renormaliza (Fan et al., 2018). Com k = 2: cheio 0,809 e verde 0,191.
  • Top-p (nucleus): restringe ao menor conjunto cuja probabilidade acumulada atinge p (Holtzman et al., 2020). Com p = 0,9, o conjunto é {cheio, verde, vazio, aberto} (acumulado 0,978), renormalizado para 0,637; 0,150; 0,117; 0,096.
  • Busca em feixe (beam search): mantém várias sequências candidatas em paralelo e escolhe a de maior probabilidade total.

Fechamento do ciclo. O token escolhido é anexado à entrada e todo o fluxo se repete, aproveitando o KV cache, até que um token de fim de sequência seja gerado ou se atinja o limite de comprimento.

12. Estudo de caso: desambiguação de "banco" e interpretabilidade

Função desta seção. Integra as etapas 3 a 9 em um único exemplo mínimo. É necessária porque, sem ela, cada mecanismo ficaria descrito isoladamente, e não se veria como eles juntos resolvem a ambiguidade de "banco".

O problema. "Banco" pode designar uma instituição financeira ou um assento. A tokenização atribui o mesmo ID nos dois casos, e o embedding de entrada é o mesmo (seções 3 e 4). O modelo não consulta um dicionário nem aplica regras do tipo se … então. O que distingue os sentidos é o contexto: a atenção mistura no vetor de "banco" informação dos tokens vizinhos, e esse vetor misturado, nas camadas seguintes, passa a se comportar de modo diferente.

Evidência empírica. Em modelos treinados, os vetores contextualizados da mesma palavra tendem a formar agrupamentos separados conforme o sentido (Reif et al., 2019), e as representações ficam mais específicas ao contexto nas camadas mais altas (Ethayarajh, 2019).

Demonstração numérica (brinquedo didático). Embeddings de 4 dimensões escolhidos à mão, com eixos [dinheiro, assento, pessoas, madeira]: banco = [0,7; 0,7; 0; 0] (ambíguo), lotado = [0; 0; 1; 0], clientes = [0,8; 0; 0,7; 0], praça = [0; 0,8; 0; 0,2], madeira = [0; 0,3; 0; 1], velho = [0; 0,2; 0; 0,5], estava = [0; 0; 0,1; 0]; os artigos "O", "da" e "de" são vetores nulos. Atenção de uma cabeça com Wq = Wk = 2·I, Wv = I e d_k = 4. Em cada contexto, calcula-se o vetor contextualizado de "banco" e compara-se, por similaridade de cosseno, com dois protótipos: instituição financeira = [1; 0; 0,5; 0] e assento = [0; 1; 0; 0,5].

Contexto Maior peso de atenção de "banco" Vetor contextualizado Cosseno com instituição Cosseno com assento
Isolado: "banco" 1,000 (ele mesmo) [0,700; 0,700; 0; 0] 0,632 0,632
"O banco estava lotado de clientes" 0,501 (ele mesmo); 0,216 (clientes) [0,524; 0,351; 0,229; 0] 0,851 0,468
"O banco da praça estava velho de madeira" 0,443 (ele mesmo); 0,191 (praça) [0,310; 0,509; 0,006; 0,175] 0,452 0,858

Isolado, o vetor é equidistante dos dois sentidos (0,632 contra 0,632). No contexto de "lotado de clientes", ele se aproxima da instituição (0,851 contra 0,468). No contexto de "praça … madeira", aproxima-se do assento (0,858 contra 0,452). O mecanismo é o mesmo nos dois casos; só mudam os vizinhos. Em um modelo real, os pesos Wq, Wk, Wv e o conhecimento nas FFNs resultam do treino, e a distinção se distribui por muitas cabeças e camadas, não por um único passo como neste brinquedo.

Por que isso surge do treino. Para prever bem a palavra seguinte em frases como "O banco estava lotado de ___", o modelo precisa registrar se a frase trata de uma agência ou de um assento. Estatisticamente, "lotado" co-ocorre com clientes, filas e agências. A representação do sentido é, portanto, um subproduto útil da minimização do erro de predição (seção 13).

Cuidados na interpretação dos mapas de atenção. Visualizar pesos de atenção (por exemplo, com ferramentas como a de Vig, 2019) é um primeiro passo de análise, mas peso de atenção não equivale a explicação causal: pesos diferentes podem produzir a mesma previsão, e a atenção de uma camada é apenas uma parte do cálculo (Jain e Wallace, 2019; Wiegreffe e Pinter, 2019). Conclusões sobre o que o modelo "usa" exigem experimentos de intervenção ou análise de circuitos (Elhage et al., 2021; Olsson et al., 2022).

13. Propriedades emergentes e leis de escala

Função desta seção. Explica por que um comportamento como a desambiguação pode existir sem ter sido programado, o que liga o resultado da seção 12 ao treino da seção 10. É necessária para situar o debate sobre emergência sem afirmar mais do que a literatura sustenta.

Conceito. Uma propriedade emergente é uma característica do sistema como um todo que não está programada em nenhum de seus componentes e surge da interação entre eles em grande número (Anderson, 1972). No Transformer, o código contém apenas multiplicações de matrizes, somas, normalizações e softmax; a meta de treino é apenas prever o próximo token. Nada ali menciona sentidos de palavras, sintaxe ou raciocínio, e ainda assim representações desse tipo aparecem nos pesos aprendidos (seções 9 e 12). A analogia usual é a do formigueiro: nenhuma formiga individual "sabe" construir uma ponte, mas a colônia a constrói.

Habilidades emergentes com a escala. Wei et al. (2022a) definem como emergente uma habilidade ausente em modelos menores e presente em modelos maiores, de modo que não se prevê sua aparição por extrapolação simples das curvas dos modelos menores. Exemplos discutidos na literatura incluem o few-shot prompting em grandes modelos (Brown et al., 2020) e o raciocínio por cadeia de pensamento (Wei et al., 2022b).

Leis de escala. Enquanto a perda média de predição melhora de modo suave e previsível com parâmetros, dados e computação (Kaplan et al., 2020; Hoffmann et al., 2022), o desempenho em tarefas específicas pode parecer mudar de forma abrupta. Ganguli et al. (2022) discutem essa combinação de previsibilidade na perda e surpresa nas capacidades.

Debate: emergência real ou efeito da métrica? Schaeffer et al. (2023) argumentam que parte dos saltos observados decorre de métricas descontínuas, como acerto exato, e que métricas contínuas sobre os mesmos modelos mostram progresso gradual. O debate permanece aberto, e a literatura recomenda cautela ao afirmar que uma capacidade "surge de repente".

Não confundir com grokking. O termo grokking designa um fenômeno distinto: em tarefas algorítmicas pequenas, a generalização aparece muito depois de o modelo já ter memorizado o conjunto de treino (Power et al., 2022), e foi analisado com técnicas de interpretabilidade mecanicista (Nanda et al., 2023). Ele ocorre ao longo do tempo de treino, e a emergência por escala ocorre ao longo do tamanho do modelo.

Aplicação ao caso "banco". A desambiguação de sentidos comuns já é observada em modelos relativamente pequenos, como o BERT-base, com 110 milhões de parâmetros (Reif et al., 2019). Portanto, não há base para afirmar um limiar fixo de camadas ou de parâmetros a partir do qual essa capacidade "aparece". O que a literatura sustenta é que a capacidade resulta do treino e que sua qualidade e abrangência crescem com a escala.

Implicações. Se capacidades podem surgir sem serem projetadas, a avaliação e a interpretabilidade tornam-se parte central do desenvolvimento: é preciso testar o modelo, e não apenas ler o código, para saber o que ele faz (Ganguli et al., 2022; Olsson et al., 2022).

14. Limitações, ressalvas e debates em aberto

Função desta seção. Delimita o que o documento mostra e o que não mostra. É necessária porque os exemplos são simplificados e porque o próprio mecanismo tem limites e pontos em debate que o leitor deve conhecer.

Limitações deste documento.

  • Os exemplos numéricos usam dimensões minúsculas, uma única cabeça e pesos escolhidos à mão ou aleatórios. Mostram a aritmética, não o comportamento de um modelo treinado.
  • Foram omitidos, por simplicidade: vieses em todas as projeções, dropout, a atenção cruzada (cross-attention) do decodificador do modelo original, e variantes como misturas de especialistas (mixture of experts) e arquiteturas alternativas à atenção, como modelos de espaço de estados (Gu e Dao, 2023).
  • Detalhes como o número exato de camadas, a função de ativação, o tipo de normalização e a codificação posicional variam entre modelos e nem sempre são divulgados.

Debates e limitações do próprio mecanismo.

  • Atenção e explicação. Pesos de atenção não são, por si sós, uma explicação confiável do comportamento do modelo (Jain e Wallace, 2019; Wiegreffe e Pinter, 2019).
  • Custo quadrático e contexto longo. O custo da atenção cresce com o quadrado do comprimento da sequência, e modelos de contexto longo podem usar pior a informação situada no meio do contexto (Liu et al., 2024).
  • Alucinação. O modelo calcula tokens prováveis dado o contexto; não há, na arquitetura, um passo que verifique a veracidade do que gera. Saídas fluentes porém factualmente incorretas são um problema documentado (Ji et al., 2023).
  • "Só estatística" ou "modelo de mundo"? Há posições divergentes. Uma sustenta que modelos treinados apenas com forma textual não alcançam compreensão de significado (Bender e Koller, 2020). Outra reúne evidências de que modelos treinados para prever o próximo token podem construir representações internas de estruturas do domínio, como o estado de um tabuleiro de Othello (Li et al., 2023). A caracterização de "compreensão" permanece em discussão, e este documento se limita a descrever os mecanismos e as evidências citadas.
  • Emergência. Ver seção 13: a natureza dos saltos de capacidade com a escala é debatida (Wei et al., 2022a; Schaeffer et al., 2023).

15. Da inferência à execução governada: implicações para o SGAEIA

Função desta seção. Esta seção estabelece a ponte entre a mecânica interna do Transformer e o problema arquitetural investigado pelo SGAEIA. Sua classificação epistemológica é SGAEIA Interpretation: trata-se de uma leitura conceitual e pública dos mecanismos descritos neste artigo, e não de evidência de implementação, eficácia, certificação ou validação em produção do SGAEIA.

A inferência termina, no limite deste artigo, com uma distribuição de probabilidades e a seleção de um token. Um sistema agentivo acrescenta outras camadas: memória, planejamento, ferramentas, credenciais, delegação, políticas, runtime e capacidade de modificar estado externo. Por isso, a saída do modelo deve ser tratada como uma proposta ou sinal computacional, não como autorização para produzir um efeito. Essa separação entre capacidade do modelo e ação governada é central na arquitetura pública do SGAEIA e em sua análise da transição do modelo para o agente (Silva, 2026a; Silva, 2026b; Silva, 2026c).

Essa separação é particularmente importante porque interpretabilidade parcial não elimina a necessidade de controles externos. Pesos de atenção, estados intermediários, explicações geradas e cadeias de raciocínio podem fornecer sinais úteis, mas nenhum deles demonstra sozinho a causa completa de uma decisão, a legitimidade de uma ação ou a estabilidade futura do comportamento. A formulação pública do SGAEIA trata essa limitação como um problema de supervisão: quanto menor a confiança na compreensão do processo interno, menos a segurança pode depender exclusivamente dessa compreensão e mais deve depender de autoridade limitada, execução mediada, revogação e recuperação (Silva, 2026d).

Também é necessário distinguir observabilidade de evidência. Registrar prompt e resposta ajuda a reconstruir parte da interação, mas não basta para demonstrar qual identidade iniciou a operação, que política estava vigente, qual autoridade permitiu uma ferramenta, que delegações ocorreram e qual efeito foi realmente observado. Em sistemas distribuídos ou multiagentes, traces e spans ajudam a reconstruir trajetórias, enquanto avaliação e evidência governada respondem a perguntas diferentes sobre resultado, legitimidade e assurance. Essa relação entre rastreamento, avaliação e evidência é analisada na pesquisa pública do SGAEIA sobre execução de agentes (Silva, 2026e).

O vínculo com o SGAEIA não transforma os exemplos didáticos deste artigo em controles arquiteturais. A tabela acima organiza questões de pesquisa e propriedades públicas em nível alto, preservando a fronteira entre explicação e mecanismo privado. A conclusão operacional é limitada, mas importante: entender como um LLM produz um token é condição necessária para governar um sistema baseado em LLMs, porém não é condição suficiente para autorizar, observar, conter ou assegurar os efeitos desse sistema.

16. Conclusão

Abrir a caixa-preta da inferência permite acompanhar a transformação do texto em IDs, vetores, relações de atenção, representações contextuais, logits e probabilidades. Os exemplos reduzidos mostram a aritmética de cada etapa e tornam explícito onde entram os pesos aprendidos, as máscaras, a normalização, a não linearidade e a regra de decodificação. Eles também deixam claro o limite da demonstração: números didáticos explicam o mecanismo, mas não medem um modelo real nem sustentam, por si sós, afirmações sobre raciocínio, segurança ou confiabilidade.

O estudo de caso de “banco” evidencia por que a representação de um token não permanece estática depois que o contexto atravessa as camadas. Ao mesmo tempo, as ressalvas sobre mapas de atenção, emergência e alucinação impedem que a explicação matemática seja confundida com transparência causal completa. A inferência é probabilística, contextual e dependente de pesos, configuração e estratégia de decodificação; sua análise deve preservar essas condições em vez de converter fluência em certeza.

Para o SGAEIA, a principal implicação é a separação entre inferência e efeito. O modelo pode propor um caminho, mas a autoridade determina se esse caminho é alcançável, e políticas e evidências determinam se ele pode tornar-se uma ação legítima. Portanto, abrir a caixa-preta de um sistema agentivo exige explicar não apenas como o token foi produzido, mas também quem autorizou cada ação, sob quais limites, com quais registros e com que capacidade de interrupção, revogação e recuperação.

import re, collections
vocab={"l o w </w>":5,"l o w e r </w>":2,"n e w e s t </w>":6,"w i d e s t </w>":3}
def stats(v):
    p=collections.Counter()
    for w,f in v.items():
        s=w.split()
        for a,b in zip(s,s[1:]): p[(a,b)]+=f
    return p
def merge(pair,v):
    out={}
    bg=re.escape(" ".join(pair)); pat=re.compile(r'(?<!\S)'+bg+r'(?!\S)')
    for w,f in v.items(): out[pat.sub("".join(pair),w)]=f
    return out
for i in range(8):
    p=stats(vocab); best=max(p,key=lambda k:(p[k],))

19.7 Auditoria dos links por requisição HTTP

Arquivo: 08_auditar_links.py. O que realiza. Abre cada URL do CSV, registra o código HTTP e a URL final, extrai o título da página e o compara com o título esperado, classificando cada entrada como OK ou REVISAR. Requer a biblioteca requests e acesso à internet. Foi testado apenas contra um servidor local, e não contra os sites reais.

Alimenta. Arquivo auditoria_links_resultado.csv, a ser gerado pelo leitor (seção 18).

#!/usr/bin/env python3
"""Audita os links da bibliografia: abre cada URL, registra o código HTTP, a URL final
e compara o <title> da página com o título esperado. Uso: python3 auditar_links.py
Requer: pip install requests. Saída: auditoria_links_resultado.csv"""
import csv, re, sys, time, difflib, html
import requests

H = {"User-Agent": "Mozilla/5.0 (auditoria-bibliografia; contato: ORCID 0009-0008-2411-6995)"}

def norm(t):
    return re.sub(r"[^a-z0-9 ]", "", html.unescape(t).lower())

def titulo(txt):
    m = re.search(r"<title[^>]*>(.*?)</title>", txt, re.S | re.I)
    return re.sub(r"\s+", " ", m.group(1)).strip() if m else ""

rows = list(csv.DictReader(open("links_bibliografia.csv", encoding="utf-8-sig")))
out = []
for r in rows:
    url, esp = r["url"], r["titulo_esperado"]
    try:
        resp = requests.get(url, headers=H, timeout=25, allow_redirects=True)
        t = titulo(resp.text) if "html" in resp.headers.get("content-type", "") else ""
        sim = difflib.SequenceMatcher(None, norm(esp), norm(t)).ratio() if t else 0.0
        contem = norm(esp)[:40] in norm(t) if t else False
        # PDFs não têm <title>: apenas o status é verificável automaticamente
        ok = resp.status_code == 200 and (contem or sim >= 0.6 or not t)
        res = [r["n"], r["autor"], url, resp.status_code, resp.url, t[:90], round(sim, 2),
               "OK" if ok else "REVISAR (conferir título manualmente)"]
    except Exception as e:
        res = [r["n"], r["autor"], url, "erro", "", str(e)[:90], 0, "REVISAR (falha de acesso)"]
    out.append(res); print(res[0], res[3], res[7], url)
    time.sleep(1.0)
with open("auditoria_links_resultado.csv", "w", newline="", encoding="utf-8-sig") as f:
    w = csv.writer(f)
    w.writerow(["n", "autor", "url", "http", "url_final", "titulo_da_pagina", "similaridade", "resultado"])
    w.writerows(out)
print("\nConcluído:", sum(1 for o in out if o[7] == "OK"), "OK de", len(out))
