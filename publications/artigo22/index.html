Abstract

This article provides a technical, formal, and didactic explanation of the inference process in Transformer-based language models, from input tokenization to next-token selection. It combines formulas, reproducible numerical examples, and six figures to explain embeddings, positional encoding, self-attention, masks, residual connections, normalization, feed-forward networks, logits, softmax, and decoding strategies. A small-scale case study of the ambiguous Portuguese word banco demonstrates how context changes representations without claiming to reproduce the behavior of a real trained model. Finally, the article distinguishes model inference from the governed execution of an agentic system and presents a public, non-normative interpretation of the implications for SGAEIA.

Keywords: AI; Transformer; inference; LLM; attention; tokenization; embeddings; softmax; emergent properties; SGAEIA.

1. Introduction and scope

Purpose of this section. It establishes the objective, conventions, and limits of the article before introducing any technique. This is necessary because the numbers and figures that follow are didactic; without this notice, they could be mistaken for measurements of a real model.

This document describes, step by step, what occurs inside a language model based on the Transformer architecture (Vaswani et al., 2017), from input text to output token. The recurring example is the ambiguous Portuguese sentence “O banco estava lotado” (“The bank was crowded/full”). The objective is to make the “black box” intelligible: each stage presents the concept, the mathematical mechanism, the adopted technique, a numerical example, and its supporting references.

Conventions. In-text references follow the (Author, year) format and are listed in Section 18. Technical terms appear in bold on first occurrence and are defined in the Glossary (Section 17). Matrices are written in uppercase (Q, K, V), and dimensions are written as n (sequence length), d_model (model dimension), and d_k (dimension of each head).

Notice on the numerical examples. The values in Sections 3–11 were calculated in Python/NumPy using reduced dimensions and hand-selected vectors for didactic purposes. They illustrate the arithmetic of the mechanism; they are not measurements of a real trained model. In real models, the weights are learned and the dimensions are much larger (for example, d_model = 512 in the original Transformer and 768 in BERT-base).

Scope. The article describes the Transformer in general terms, covering encoder-only, decoder-only, and encoder–decoder variants.

2. Overview of the inference flow

Why the flow contains these stages in this order. Each stage solves a problem left open by the previous one. The network operates only on numbers (tokenization); integer IDs have neither geometry nor order (embeddings and position); each token needs context (attention); the contextual mixture must be transformed, stabilized, and repeated in depth (FFN, Add & Norm, stacking); behavior depends on weights that must be learned (training); and the final result must become a token (logits, softmax, and decoding). The table summarizes the problem solved by each stage and what would be missing without it.

Stage Problem it solves Without it
Tokenization The network only processes numbers, and the vocabulary must be finite There is no numeric input; rare words would lack a representation or sequences would become too long
Embedding Integer IDs are arbitrary labels with no notion of similarity Each token would be a sparse one-hot vector with one dimension per vocabulary token and no similarity between tokens
Positional encoding Attention does not inherently use word order Unmasked attention cannot distinguish different orders of the same words (Vaswani et al., 2017)
Self-attention Each token needs information from other tokens Each token would be interpreted in isolation; banco would always have the same vector
Multi-head attention Multiple relationships must be captured at the same time A single weighted average per layer would constrain attention to one representational subspace (Vaswani et al., 2017)
Add & Norm Signal and gradient must cross many layers Training may become unstable or degraded in deep stacks (He et al., 2016; Ba et al., 2016; Xiong et al., 2020)
FFN Attention only combines Values; per-token transformation is still needed The component containing roughly two-thirds of the layer parameters would be absent (Geva et al., 2021)
Stacking Complex relationships require composition over multiple steps Only direct one-step relationships; some circuits require two or more layers (Elhage et al., 2021; Olsson et al., 2022)
Training Random weights do not produce language A circuit with no useful behavior, as in the random-weight examples
Output A numeric vector must become a token Without logits, softmax, and decoding there is no distribution and no selected token

Inference in a language model is the execution of an already-trained model with fixed weights to produce an output from an input. In a generative model, execution is cyclical: the model calculates a probability distribution over the next token, a token is selected and appended to the input, and the cycle repeats (autoregressive generation). A complete computation through all layers is called a forward pass.

The original architecture combines an encoder and a decoder (Vaswani et al., 2017). Two derivative families dominate current use: encoder-only models, such as BERT (Devlin et al., 2019), which observe the sequence in both directions, and decoder-only models, such as the GPT series (Radford et al., 2018; Radford et al., 2019; Brown et al., 2020), which generate text from left to right. The mechanisms described in the following sections apply to all of them, with the primary difference being the attention mask (Section 6).

Stage Operation Main technique Key reference
1. Tokenization Text → integer IDs BPE, SentencePiece Sennrich et al., 2016; Kudo and Richardson, 2018
2. Embedding and position IDs → vectors + order Embedding matrix; sinusoidal encoding or RoPE Mikolov et al., 2013; Vaswani et al., 2017; Su et al., 2021
3. Self-attention Contextual mixing among tokens Scaled dot product and softmax Bahdanau et al., 2015; Vaswani et al., 2017
4. Multi-head attention Multiple relationships in parallel Subspaces of dimension d_k Vaswani et al., 2017; Voita et al., 2019
5. Add & Norm Signal stability Residual connection; LayerNorm, RMSNorm He et al., 2016; Ba et al., 2016; Zhang and Sennrich, 2019
6. FFN Nonlinear transformation at each position MLP with ReLU, GELU, or SwiGLU Geva et al., 2021; Shazeer, 2020
7. Stacking Refinement in depth N layers Tenney et al., 2019
8. Output Logits → probabilities → token Softmax, temperature, top-k, top-p Holtzman et al., 2020

Training (Section 10) is the process that defines the weights. Inference only uses them.

3. Stage 1 — Input and tokenization

Why this stage is necessary. Computers apply arithmetic operations to numbers; without converting text into IDs, there is no input to the network. The vocabulary must be finite and fixed because the output layer has one dimension per token (Section 11). Subword tokenization addresses a real tradeoff: whole words leave new terms without a representation, whereas individual characters create long sequences and increase the cost of attention, which grows with the square of sequence length (Section 5; Sennrich et al., 2016).

Concept. Neural networks operate on numbers, not text. Tokenization converts a character string into a sequence of tokens (vocabulary units) and each token into an integer ID. The vocabulary is a finite set established before training, typically containing tens of thousands of entries.

Why subwords. Whole-word vocabularies do not represent rare or new words (the out-of-vocabulary, or OOV, problem), whereas character vocabularies produce overly long sequences. Subword units balance these extremes: frequent words become a single token, and rare words are decomposed into reusable pieces (Sennrich et al., 2016).

Techniques discussed.

  • BPE (Byte Pair Encoding): starts from characters and iteratively merges the most frequent adjacent pair into a new symbol. It was proposed by Gage (1994) as a compression algorithm and adapted to machine translation by Sennrich et al. (2016). Byte-level variants are used in GPT-series models (Radford et al., 2019).
  • WordPiece: selects merges by their increase in language-model likelihood rather than simple frequency (Schuster and Nakajima, 2012; Wu et al., 2016). It is used in BERT (Devlin et al., 2019).
  • Unigram LM and SentencePiece: Unigram starts from a large vocabulary and prunes the entries that contribute least (Kudo, 2018). SentencePiece implements BPE and Unigram directly over raw text without whitespace pre-tokenization, making it language-independent (Kudo and Richardson, 2018).

Numerical example (BPE in a didactic corpus). Consider a corpus with the following word frequencies, where </w> marks the end of a word: low (5), lower (2), newest (6), widest (3). Initially, each word is a sequence of characters. At each step, the most frequent pair is merged, with ties resolved by order of occurrence. The code produces:

Step Merged pair Pair frequency New symbol
1 e + s 9 es
2 es + t 9 est
3 est + </w> 9 est</w>
4 l + o 7 lo
5 lo + w 7 low
6 n + e 6 ne
7 ne + w 6 new
8 new + est</w> 6 newest</w>

After eight merges, newest is a single token (newest</w>), low consists of the token low followed by </w>, and widest is decomposed into w, i, d, est</w>: a word never observed as a whole reuses the est</w> piece learned from newest.

Application to the recurring sentence. In a real vocabulary, “O banco estava lotado” usually produces only a few tokens per word because the words are common in Portuguese. For this article, we adopt the simplification 4 words = 4 tokens: [O] [banco] [estava] [lotado], with illustrative integer IDs (for example, 12, 4871, 905, 23019; actual values depend on the tokenizer). The ID for banco is the same for both senses of the word: tokenization does not disambiguate. The distinction emerges only in the attention layers (Section 12).

4. Stage 2 — Embeddings and positional encoding

Why this stage is necessary. An integer ID is an arbitrary label: ID 4871 is not more similar in meaning to ID 4872. An embedding converts each label into a vector in which training can organize similarity (Bengio et al., 2003; Mikolov et al., 2013), and subsequent operations such as sums and dot products are meaningful only over vectors. Positional encoding is necessary because attention does not inherently use order: “the cat eats the fish” and “the fish eats the cat” contain the same tokens, and without position information unmasked attention treats them as equivalent up to permutation (Vaswani et al., 2017). In causally masked decoders, some positional information can be inferred from the number of visible tokens, but explicit positional encoding remains standard practice.

Embedding. Each ID selects one row from a weight matrix W_E of dimension |V| × d_model, producing a dense vector that represents the token. The idea of representing words as continuous vectors in which geometric proximity reflects similarity of use comes from neural language models (Bengio et al., 2003) and word2vec (Mikolov et al., 2013). In the Transformer, the matrix is learned jointly with the rest of the model, the vectors are multiplied by √d_model, and the same matrix is often shared with the output projection (Vaswani et al., 2017; Press and Wolf, 2017). A central point is that the input embedding is static: banco receives the same vector in every sentence. Contextualization occurs later, through attention.

Positional encoding. Attention alone treats the input as a set: permuting the tokens permutes the output in the same way without distinguishing order. A position-dependent vector is therefore added to the embedding. The original proposal uses sinusoidal functions at geometrically varying frequencies (Vaswani et al., 2017):

$$PE_{(pos,,2i)} = \sin!\left(\frac{pos}{10000^{2i/d_{model}}}\right), \qquad PE_{(pos,,2i+1)} = \cos!\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

Each pair of dimensions oscillates at a different frequency, and the difference between positions can be expressed as a linear transformation of the vectors, which facilitates learning relative-distance relationships (Vaswani et al., 2017).

Alternatives used in the literature.

  • Learned positions: a trainable table used in BERT and GPT-2 (Devlin et al., 2019; Radford et al., 2019).
  • Relative positions: attention becomes dependent on the distance between tokens (Shaw et al., 2018).
  • RoPE (rotary position embeddings): rotates Q and K according to position, encoding relative position in the dot product itself (Su et al., 2021). It is used in models such as LLaMA (Touvron et al., 2023).
  • ALiBi: adds a linear distance-dependent bias to attention scores, improving extrapolation to sequences longer than those seen in training (Press et al., 2022).

Numerical example. Let d_model = 4 (didactic; the original Transformer uses 512), with hand-selected embeddings for the four tokens and sinusoidal encoding computed by the formula above. For banco at position 1: PE = [sin(1), cos(1), sin(0.01), cos(0.01)] = [0.841; 0.540; 0.010; 1.000]. Adding the embedding [0; 1; 0.5; 0] yields x = [0.841; 1.540; 0.510; 1.000]. Figure 2 shows the three matrices; X = E + P, of dimension 4 × 4, is the input to the first layer.

5. Stage 3 — Self-attention

Why this stage is necessary. A word’s meaning depends on its neighbors, while the input embedding is static (Section 4): banco begins with the same vector in every sentence. A mechanism is needed in which each token consults the others using content-dependent rather than fixed-position weights. Recurrent models transmit information step by step, so distant dependencies cross many operations; with attention, any two positions can connect in one step, and the computation can be parallelized (Vaswani et al., 2017). Separating Query, Key, and Value is a design choice that decouples what a token seeks, what it offers for matching, and the content it passes onward. Division by √d_k prevents softmax saturation when d_k is large.

Concept. Self-attention allows each token to recompute its representation as a weighted average of the representations of every token in the sequence, including itself, with content-dependent weights. Attention first emerged in machine translation to align output words with input words (Bahdanau et al., 2015), and the Transformer generalized it to operate from a sequence onto itself (Vaswani et al., 2017).

Three roles per token. Three trainable weight matrices project each input vector:

  • Query (Q = X·Wq): what this token is looking for.
  • Key (K = X·Wk): what this token offers for matching.
  • Value (V = X·Wv): the content this token passes on when selected.

Formula (scaled dot-product attention).

$$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V$$

  • QKᵀ measures compatibility between each Query and each Key (a high dot product means that the vectors point in similar directions).
  • Division by √d_k: if the components of q and k have mean 0 and variance 1, the dot product has variance d_k. Without scaling, scores grow with dimensionality and push softmax into regions with near-zero gradients (Vaswani et al., 2017).
  • Softmax: converts each row of scores into positive weights that sum to 1.
  • Multiplication by V: the result is the weighted average of the Values, yielding the contextualized token.

Numerical example (d_model = 4, d_k = 2, values calculated by code). Using X from Section 4 and hand-selected Wq, Wk, and Wv matrices, the following values are obtained for the token banco at position 1:

Step O banco estava lotado
Score q·k (QKᵀ) 4,476 6,130 5,353 4,375
Score / √2 3,165 4,334 3,785 3,093
Weight (softmax) 0.143 0.459 0.265 0.133

The weights sum to 1.000. The output for banco is Z = 0.143·v_O + 0.459·v_banco + 0.265·v_estava + 0.133·v_lotado = [1.043; 1.360], where v_O = [1.000; 1.500], v_banco = [1.096; 2.040], v_estava = [1.419; 0.384], and v_lotado = [0.156; 0.810]. The vector for banco is no longer only banco: it incorporates information from the other tokens in proportion to the attention weights. Because the weights in this example were selected by hand, no linguistic meaning should be inferred from the resulting pattern; in a trained model, Wq, Wk, and Wv learn which relationships matter.

How to read the map (Figure 4). Rows are Queries (who asks); columns are Keys (who is attended to); each row sums to 1. On the left, every token can attend to every other token (encoder style). On the right, the causal mask sets future positions to zero (Section 6).

Cost. The score matrix contains n × n entries, so time and memory grow quadratically with sequence length. Implementations such as FlashAttention reduce memory traffic without changing the mathematical result (Dao et al., 2022).

6. Stage 4 — Multi-head attention and masks

Why this stage is necessary. A single attention operation produces only one weighted average per token, which, according to Vaswani et al. (2017), inhibits simultaneous attention to information from different representational subspaces. Multiple heads allow different relationships to be modeled in parallel without increasing total cost because each head operates in a smaller dimension. The causal mask is necessary for generation: during training, the entire text is available, and without the mask the model would “see” the token it must predict, learn to copy it, and then fail during inference, where the future does not exist. The padding mask prevents empty positions from influencing the result. Shared K/V variants and the KV cache exist because rereading and recomputing the entire past for every generated token would otherwise be prohibitive (Pope et al., 2023).

Concept. A single attention operation produces one weighted average per token. Multi-head attention executes h attention operations in parallel, each with its own Wq, Wk, and Wv matrices and operating in a subspace of dimension d_k = d_model / h. The head outputs are concatenated and projected through a Wo matrix (Vaswani et al., 2017):

$$\mathrm{MultiHead}(X) = \mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h),W^{O}, \qquad \mathrm{head}_i = \mathrm{Attention}(XW^{Q}_i,,XW^{K}_i,,XW^{V}_i)$$

Numerical example (original Transformer, base configuration). With d_model = 512 and h = 8, each head has d_k = d_v = 64, and total computational cost is similar to that of a single head with dimension 512 (Vaswani et al., 2017). Together, the four projection matrices in one attention layer contain 4 × 512 × 512 = 1,048,576 weights, excluding biases. For internal consistency, h must divide d_model; therefore, 12 heads do not apply to d_model = 512. BERT-base uses 12 heads with d_model = 768, yielding d_k = 64 (Devlin et al., 2019).

Why multiple heads. Each head can learn a different type of relationship. Attention analyses in BERT have identified heads that focus on delimiters, fixed positional offsets, and syntactic relationships such as verbs and direct objects (Clark et al., 2019). There is also evidence that many heads are redundant: a small subset accounts for most of the performance, and the remainder can be pruned with little loss (Voita et al., 2019; Michel et al., 2019).

Variants for efficient inference. In Multi-Query Attention, all heads share a single pair of K and V matrices (Shazeer, 2019). In Grouped-Query Attention, groups of heads share K and V, providing a compromise between quality and memory use (Ainslie et al., 2023). Both reduce the size of the KV cache, which stores previously computed K and V values so that the past need not be recomputed for each newly generated token (Pope et al., 2023).

Attention masks.

  • Bidirectional (encoder): each position can attend to every other position. This is the BERT regime (Devlin et al., 2019).
  • Causal (decoder): before softmax, scores for future positions receive −∞, making their weights exactly 0. This preserves the autoregressive property: the prediction at position t depends only on positions up to t (Vaswani et al., 2017; Radford et al., 2019).
  • Padding: ignores empty positions used to equalize sequence lengths within a batch.

Numerical example of the causal mask. In the row for banco, the scaled scores were [3.165; 4.334; 3.785; 3.093]. With a causal mask, the final two positions (estava and lotado, which are in the future) become −∞, and softmax over [3.165; 4.334] yields [0.237; 0.763; 0; 0]. Therefore, in a generative model, banco cannot attend to lotado; disambiguation using later words occurs only after they have been read, at subsequent positions. In bidirectional models, such as the left-hand map in Figure 4, forward attention is permitted.

7. Stage 5 — Residual connection and normalization (Add & Norm)

Why this stage is necessary. Stacking many layers requires both the signal and the training gradient to pass through many transformations. Without a shortcut, deeper networks may perform worse during training, a degradation problem mitigated by residual connections (He et al., 2016). The residual path also preserves the original information and lets each sublayer learn only a correction. Normalization keeps value scales stable with depth (Ba et al., 2016), while its position (Pre-LN or Post-LN) affects training stability when careful warm-up is absent (Xiong et al., 2020). Without these mechanisms, the depth that gives the model capacity could not be trained reliably.

Residual connection. After each sublayer (attention or FFN), the sublayer input is added to its output: y = x + Sublayer(x). The idea comes from residual networks in computer vision (He et al., 2016). It creates a direct path for the signal and gradient, enabling deep stacks to be trained, and causes each sublayer to learn a correction to what already exists rather than reconstructing everything. In circuit interpretations, this path is the residual stream, a channel that every layer reads from and writes to (Elhage et al., 2021).

Normalization. Without scale control, values may grow or shrink across layers and destabilize training. LayerNorm normalizes each token separately across its d_model components, not across the batch, and then applies a learned scale γ and shift β (Ba et al., 2016):

$$\mathrm{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^{2} + \epsilon}} + \beta, \qquad \mu = \tfrac{1}{d}\sum_i x_i, \quad \sigma^{2} = \tfrac{1}{d}\sum_i (x_i - \mu)^2$$

RMSNorm omits mean subtraction and normalizes only by the root mean square, at lower cost and with comparable performance (Zhang and Sennrich, 2019); it is used in models such as LLaMA (Touvron et al., 2023).

Post-LN and Pre-LN. The original Transformer applies normalization after the residual addition (Post-LN). Many current models apply it before each sublayer (Pre-LN), a variant that trains more stably and reduces dependence on careful learning-rate warm-up (Xiong et al., 2020).

Numerical example (token banco, causal version, γ = 1, β = 0). The attention output projected by Wo is o = [1.074; 1.912; 0.537; 0.956]. The input was x = [0.841; 1.540; 0.510; 1.000]. Residual addition gives r = x + o = [1.915; 3.453; 1.047; 1.956]. The mean is μ = 2.093 and the variance is σ² = 0.748. LayerNorm with ε = 10⁻⁵ gives [(1.915 − 2.093)/0.865; …] = [−0.205; 1.572; −1.209; −0.158], with mean 0 and variance 1. By comparison, RMSNorm of the same vector, with root mean square 2.264, yields [0.846; 1.525; 0.462; 0.864]: it preserves the proportions among components without centering them at zero.

8. Stage 6 — Feed-forward network (FFN)

Why this stage is necessary. In attention, the weights depend on content, but the output is a weighted average of Values obtained through linear projections (V = X·Wv, followed by Wo); the only nonlinearity is the softmax that determines the weights. The FFN adds a nonlinear transformation applied to each token after contextual information has been assembled. There is also a capacity rationale: FFNs contain roughly two-thirds of a Transformer’s parameters and act as memories for patterns (Geva et al., 2021). Expanding to d_ff = 4 × d_model in the original model is a design choice that increases this capacity (Vaswani et al., 2017).

Concept. After attention, each position passes through a small neural network with two linear layers and a nonlinearity between them, applied independently to each token with the same weights at every position in the layer (Vaswani et al., 2017):

$$\mathrm{FFN}(x) = \max(0,; xW_1 + b_1),W_2 + b_2$$

Attention mixes information between tokens. The FFN transforms information within each token, expanding it to a larger dimension d_ff (2048 in the original model, or 4 × d_model), applying the nonlinearity, and compressing it back to d_model.

Activation functions. ReLU is used in the original Transformer; GELU in BERT and GPT (Hendrycks and Gimpel, 2016; Devlin et al., 2019; Radford et al., 2019); and gated variants of GLU, such as SwiGLU, in more recent models (Shazeer, 2020; Touvron et al., 2023).

Interpretation. Geva et al. (2021) propose that the FFN functions as a key–value memory: columns of W1 detect patterns in the input vector (keys), while rows of W2 contribute associated information (values). This interpretation helps explain why much factual knowledge appears to reside in FFNs rather than attention. It is an interpretive hypothesis supported by empirical analysis, not a fact demonstrated for every model.

Numerical parameter example (base Transformer). W1 contains 512 × 2048 = 1,048,576 weights and W2 contains 2048 × 512 = 1,048,576, totaling 2,097,152 per layer without biases. Adding the 1,048,576 attention weights (Section 6), the layer contains approximately 3.15 million weights, roughly two-thirds of which belong to the FFN.

Numerical computation example (d_model = 4, d_ff = 8; W1 and W2 generated randomly with a fixed seed and no training). For the token estava at position 2, the FFN input is the normalized vector [1.389; −0.901; −0.999; 0.511]. After W1 and ReLU, the hidden layer is [0.907; 0.660; 0.330; 0; 0.623; 0; 1.541; 0.759]: six of the eight units are active and two are zeroed by ReLU. After W2, the output is [0.231; 0.954; 0.437; −0.291]. Adding it to the input through the residual path and normalizing yields [1.613; −0.351; −1.121; −0.141]. For banco at position 1, all eight hidden units are zero in this example, so the FFN output is zero and the vector crosses the sublayer unchanged through the residual path. In a trained model, the sparse activation pattern is learned, and each token activates a different subset of units.

9. Stage 7 — Multilayer stacking

Why this stage is necessary. One layer captures relationships in one step. Many tasks require composition: identify the token, relate it to context, infer its sense, and only then predict. Stacking enables successive refinement, and probing analyses reveal different levels of information across layers (Jawahar et al., 2019; Tenney et al., 2019; Belrose et al., 2023). Some documented mechanisms, such as induction heads, require at least two attention layers (Elhage et al., 2021; Olsson et al., 2022). More layers increase both capacity and cost, so depth is a design choice, as shown below.

Mechanism. A Transformer block follows the sequence attention → Add & Norm → FFN → Add & Norm. The model stacks N blocks: the output of layer l becomes the input to layer l + 1, and each layer has its own weights. The n × d_model matrix retains the same shape across the stack; what changes is the content of each vector as it is progressively refined.

Model Layers d_model Heads Parameters Source
Transformer base (original) 6 + 6 512 8 65 million Vaswani et al., 2017
BERT-base 12 768 12 110 million Devlin et al., 2019
BERT-large 24 1024 16 340 million Devlin et al., 2019
GPT-3 (largest version) 96 12288 96 175 billion Brown et al., 2020

What different depths tend to represent. Probing studies in BERT indicate an approximate progression: early layers capture surface and local-order patterns; intermediate layers capture syntactic structure; and higher layers capture semantic and long-range relationships (Jawahar et al., 2019). Tenney et al. (2019) observed that stages of the classical NLP pipeline—part-of-speech tagging, syntactic parsing, entities, semantic roles, and coreference—can be recovered in that order across the layers. Figure 5 summarizes this tendency.

Iterative refinement of the prediction. Techniques such as the logit lens and tuned lens project the intermediate state of each layer onto the vocabulary and show that the predicted next-token distribution becomes more precise layer by layer (Belrose et al., 2023).

Circuits that require depth. Induction heads are a documented example: one head in an earlier layer copies information from the previous token, and a later head uses it to locate past occurrences of a pattern and predict its continuation. This mechanism requires at least two attention layers and has been associated with the emergence of in-context learning during training (Elhage et al., 2021; Olsson et al., 2022).

Caveat. Layer boundaries vary with the model, task, and analytical method. Layer ranges used in didactic explanations—for example, “layer 6 resolves the sense of banco”—are illustrations, not results measured in this article.

10. Stage 8 — Weights: what they are and how they are learned

Why this stage is necessary. With random weights, the previous stages produce outputs unrelated to language, as in the numerical examples in this article. Training is what turns the architecture into a useful model. Next-token prediction is an effective objective because it provides a learning signal from any text without human labels. Backpropagation is necessary because millions to billions of parameters can only be adjusted using efficiently computed gradients (Rumelhart et al., 1986), while the optimizer, warm-up, and regularization stabilize those updates (Kingma and Ba, 2015; Loshchilov and Hutter, 2019; Vaswani et al., 2017). This stage also explains why inference uses fixed weights: what the model has learned is already encoded in them.

What weights are. Weights, or parameters, are the adjustable numbers in the model: the embedding matrix; Wq, Wk, Wv, Wo, W1, W2, biases, and the normalization parameters γ and β in each layer; and the final vocabulary projection. They remain fixed during inference. Everything the model has learned is encoded in these values.

Training objective. Generative models are trained to predict the next token. Given a sequence x₁…x_T, training minimizes the mean cross-entropy between the predicted distribution and the token that actually follows:

$$\mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta!\left(x_t \mid x_{<t}\right), \qquad \mathrm{PPL} = e^{\mathcal{L}}$$

BERT uses a different objective, masked language modeling, in which some tokens are hidden and the model reconstructs them using context from both directions (Devlin et al., 2019). In both cases, there is no human label for meaning: the signal is the text itself. This supports the idea that disambiguation is an emergent strategy for reducing prediction error (Section 13).

Numerical example. In the output computed in Section 11 using random weights, the probability assigned to lotado is p = 0.022 and the probability assigned to cheio is 0.623. If the correct token were lotado, the loss would be −ln(0.022) = 3.806; if it were cheio, the loss would be −ln(0.623) = 0.473. The loss gradient with respect to the logits is simply p − y, where y is the one-hot vector for the correct token. For target lotado, the gradient is [−0.978; 0.114; 0.623; 0.094; 0.147], meaning that training pushes the lotado logit upward and the others downward in proportion to the error.

Backpropagation and optimization. The gradient is propagated backward through all layers by the chain rule, an algorithm known as backpropagation (Rumelhart et al., 1986), and an optimizer updates the weights. The original Transformer used Adam (Kingma and Ba, 2015) with a learning rate that grows linearly during warm-up and then decays, together with dropout and label smoothing (Vaswani et al., 2017). AdamW, which decouples weight-decay regularization from the adaptive update, is a common choice in current models (Loshchilov and Hutter, 2019).

Parallelism in training and sequence in inference. During training with a causal mask, all positions are computed at once because the correct text is already known. During inference, token t + 1 depends on the selected token t, so generation is sequential, and the KV cache (Section 6) prevents recomputation of the past.

Training phases. A common practice is pretraining on a large volume of raw text, followed by adaptation for specific use through supervised fine-tuning and alignment with human preferences, such as reinforcement learning from human feedback (Ouyang et al., 2022).

Scale. Language-model loss decreases regularly according to power laws as parameters, data, and compute increase (Kaplan et al., 2020). Hoffmann et al. (2022) showed that, for a fixed compute budget, parameters and data volume should grow proportionally and that many large models had been undertrained on data.

11. Stage 9 — Output: logits, softmax, and decoding

Why this stage is necessary. The final layer produces a vector of d_model values, while the user needs a token. Logits map that vector to one score per vocabulary token. Softmax converts the scores into a valid probability distribution—positive values summing to 1—which is required both for cross-entropy loss during training and for selecting or sampling a token during inference. Temperature and decoding rules are necessary because always choosing the most likely token tends to produce repetitive, degenerate text, while unrestricted sampling includes implausible tokens; top-k and top-p strategies balance these extremes (Holtzman et al., 2020).

Logits. The final-layer vector at the current position (h_final, of dimension d_model) is multiplied by an output matrix W_out of dimension d_model × |V|. The result is the logits: one unbounded real number for each vocabulary token. In many models, W_out is the transpose of the embedding matrix, a technique known as weight tying (Press and Wolf, 2017; Vaswani et al., 2017).

Softmax and temperature. Softmax converts logits into probabilities that sum to 1. Temperature T divides the logits before softmax: T < 1 concentrates probability on the most likely tokens, producing more deterministic output, whereas T > 1 spreads probability and produces greater variation. Temperature-scaled softmax was popularized in model distillation (Hinton et al., 2015).

$$p_i = \frac{e^{z_i / T}}{\sum_{j} e^{z_j / T}}$$

Numerical example. Consider a didactic vocabulary of five tokens and logits calculated from the vector at the position estava, using random untrained output weights: lotado −0.818; vazio 0.815; cheio 2.516; aberto 0.626; verde 1.070. With T = 1, softmax gives lotado 0.022; vazio 0.114; cheio 0.623; aberto 0.094; verde 0.147, summing to 1.000. With T = 0.5, cheio rises to 0.899; with T = 2, it falls to 0.402 and the distribution becomes flatter (Figure 6). In a trained model, these weights would be adjusted so that plausible words after “O banco estava,” such as lotado, receive high probability; here the example demonstrates only the arithmetic.

Decoding strategies. Selecting a token from the distribution is a separate step from the model itself:

  • Greedy: always chooses the highest-probability token; in this example, cheio.
  • Sampling: draws a token according to the probabilities.
  • Top-k: restricts sampling to the k most likely tokens and renormalizes (Fan et al., 2018). With k = 2: cheio 0.809 and verde 0.191.
  • Top-p (nucleus): restricts sampling to the smallest set whose cumulative probability reaches p (Holtzman et al., 2020). With p = 0.9, the set is {cheio, verde, vazio, aberto}, with cumulative probability 0.978, renormalized to 0.637; 0.150; 0.117; 0.096.
  • Beam search: maintains several candidate sequences in parallel and selects the one with the highest total probability.

Closing the cycle. The selected token is appended to the input, and the entire flow repeats while reusing the KV cache until an end-of-sequence token is generated or the length limit is reached.

12. Case study: disambiguating banco and interpreting the mechanism

Purpose of this section. It integrates Stages 3–9 into one minimal example. Without it, each mechanism would remain isolated and it would be unclear how they jointly resolve the ambiguity of banco.

The problem. The Portuguese word banco may denote either a financial institution or a bench. Tokenization assigns the same ID in both cases, and the input embedding is identical (Sections 3 and 4). The model does not consult a dictionary or apply explicit if … then rules. What distinguishes the senses is context: attention mixes information from neighboring tokens into the vector for banco, and in subsequent layers this mixed vector behaves differently.

Empirical evidence. In trained models, contextualized vectors for the same word tend to form separate clusters by sense (Reif et al., 2019), and representations become more context-specific in higher layers (Ethayarajh, 2019).

Numerical demonstration (didactic toy). Hand-selected four-dimensional embeddings use the axes [money, seat, people, wood]: banco = [0.7; 0.7; 0; 0] (ambiguous), lotado = [0; 0; 1; 0], clientes = [0.8; 0; 0.7; 0], praça = [0; 0.8; 0; 0.2], madeira = [0; 0.3; 0; 1], velho = [0; 0.2; 0; 0.5], estava = [0; 0; 0.1; 0]; the articles O, da, and de are null vectors. One-head attention uses Wq = Wk = 2·I, Wv = I, and d_k = 4. In each context, the contextualized vector for banco is computed and compared by cosine similarity with two prototypes: financial institution = [1; 0; 0.5; 0] and seat = [0; 1; 0; 0.5].

Context Largest attention weight for banco Contextualized vector Cosine with institution Cosine with seat
Isolated: “banco” 1.000 (itself) [0.700; 0.700; 0; 0] 0.632 0.632
“O banco estava lotado de clientes” 0.501 (itself); 0.216 (clientes) [0.524; 0.351; 0.229; 0] 0.851 0.468
“O banco da praça estava velho de madeira” 0.443 (itself); 0.191 (praça) [0.310; 0.509; 0.006; 0.175] 0.452 0.858

In isolation, the vector is equally distant from both senses (0.632 versus 0.632). In the context lotado de clientes, it moves closer to the financial-institution prototype (0.851 versus 0.468). In the context praça … madeira, it moves closer to the seat prototype (0.858 versus 0.452). The mechanism is the same in both cases; only the neighboring tokens change. In a real model, Wq, Wk, and Wv and the knowledge in the FFNs result from training, and the distinction is distributed across many heads and layers rather than one step in a toy example.

Why this emerges from training. To predict the next word in sentences such as “O banco estava lotado de ___,” the model must represent whether the sentence concerns a branch office or a seat. Statistically, lotado co-occurs with customers, queues, and branches. Sense representation is therefore a useful by-product of minimizing prediction error (Section 13).

Caution when interpreting attention maps. Visualizing attention weights—for example, with tools such as Vig (2019)—is a useful first analytical step, but attention weight is not equivalent to causal explanation: different weights can produce the same prediction, and the attention in one layer is only one part of the computation (Jain and Wallace, 2019; Wiegreffe and Pinter, 2019). Claims about what the model “uses” require intervention experiments or circuit analysis (Elhage et al., 2021; Olsson et al., 2022).

13. Emergent properties and scaling laws

Purpose of this section. It explains how a behavior such as disambiguation can exist without being explicitly programmed, linking the result of Section 12 to the training process in Section 10. It frames the debate on emergence without claiming more than the literature supports.

Concept. An emergent property is a characteristic of the system as a whole that is not programmed into any single component and arises from large-scale interaction among components (Anderson, 1972). Transformer code contains only matrix multiplications, additions, normalizations, and softmax; the training objective is only to predict the next token. Nothing explicitly names word senses, syntax, or reasoning, yet representations of this kind appear in the learned weights (Sections 9 and 12). A common analogy is an ant colony: no individual ant “knows” how to build a bridge, yet the colony builds one.

Capabilities that emerge with scale. Wei et al. (2022a) define an emergent capability as one that is absent in smaller models and present in larger models such that its appearance cannot be predicted by simple extrapolation from the smaller-model curves. Examples discussed in the literature include few-shot prompting in large models (Brown et al., 2020) and chain-of-thought reasoning (Wei et al., 2022b).

Scaling laws. While average prediction loss improves smoothly and predictably with parameters, data, and compute (Kaplan et al., 2020; Hoffmann et al., 2022), performance on specific tasks may appear to change abruptly. Ganguli et al. (2022) discuss this combination of predictability in loss and surprise in capabilities.

Debate: genuine emergence or a metric effect? Schaeffer et al. (2023) argue that some observed jumps result from discontinuous metrics, such as exact match, and that continuous metrics applied to the same models reveal gradual progress. The debate remains open, and the literature advises caution when claiming that a capability “suddenly appears.”

Do not confuse this with grokking. Grokking denotes a distinct phenomenon: in small algorithmic tasks, generalization appears long after the model has already memorized the training set (Power et al., 2022), and it has been analyzed using mechanistic interpretability techniques (Nanda et al., 2023). Grokking occurs over training time, whereas scale-based emergence occurs across model sizes.

Application to the banco case. Disambiguation of common senses is already observed in relatively small models such as BERT-base, with 110 million parameters (Reif et al., 2019). There is therefore no basis for asserting a fixed layer or parameter threshold at which the capability “appears.” The literature supports the conclusions that the capability results from training and that its quality and scope improve with scale.

Implications. If capabilities can arise without being explicitly designed, evaluation and interpretability become central to development: the model must be tested, not merely inspected at the code level, to determine what it does (Ganguli et al., 2022; Olsson et al., 2022).

14. Limitations, caveats, and open debates

Purpose of this section. It defines what the article does and does not demonstrate. This is necessary because the examples are simplified and because the mechanism itself has limitations and unresolved questions that readers should understand.

Limitations of this article.

  • The numerical examples use very small dimensions, a single head, and hand-selected or random weights. They demonstrate the arithmetic, not the behavior of a trained model.
  • For simplicity, the article omits biases in all projections, dropout, cross-attention in the decoder of the original model, and variants such as mixtures of experts and attention alternatives such as state-space models (Gu and Dao, 2023).
  • Details such as the exact number of layers, activation function, normalization type, and positional encoding vary among models and are not always disclosed.

Debates and limitations of the mechanism itself.

  • Attention and explanation. Attention weights are not, by themselves, a reliable explanation of model behavior (Jain and Wallace, 2019; Wiegreffe and Pinter, 2019).
  • Quadratic cost and long context. Attention cost grows with the square of sequence length, and long-context models may use information located in the middle of the context less effectively (Liu et al., 2024).
  • Hallucination. The model computes likely tokens given the context; the architecture contains no step that verifies the truth of what it generates. Fluent but factually incorrect output is a documented problem (Ji et al., 2023).
  • “Only statistics” or a “world model”? Positions diverge. One argues that models trained only on textual form cannot attain understanding of meaning (Bender and Koller, 2020). Another points to evidence that models trained for next-token prediction can construct internal representations of domain structure, such as the state of an Othello board (Li et al., 2023). The characterization of “understanding” remains contested, and this article is limited to the mechanisms and cited evidence.
  • Emergence. See Section 13: the nature of capability jumps with scale remains debated (Wei et al., 2022a; Schaeffer et al., 2023).

15. From inference to governed execution: implications for SGAEIA

Purpose of this section. This section bridges the Transformer’s internal mechanics and the architectural problem investigated by SGAEIA. Its epistemic classification is SGAEIA Interpretation: it is a public conceptual reading of the mechanisms described in this article, not evidence of SGAEIA implementation, effectiveness, certification, or production validation.

Within the scope of this article, inference ends with a probability distribution and the selection of a token. An agentic system adds other layers: memory, planning, tools, credentials, delegation, policies, runtime, and the ability to modify external state. Model output should therefore be treated as a proposal or computational signal, not as authorization to produce an effect. This separation between model capability and governed action is central to the public SGAEIA architecture and its analysis of the transition from model to agent (Silva, 2026a; Silva, 2026b; Silva, 2026c).

Observed component What the mechanism produces Associated governance question SGAEIA interpretation
Input, tokenization, and context Numerical representation conditioned on supplied data Origin, integrity, sensitivity, and boundaries of context Input provenance must remain distinguishable from the interpretation produced by the model
Attention, layers, and KV cache Intermediate contextual state and reuse of prior information Confidentiality, isolation, retention, and state contamination State useful for inference is not equivalent to memory authorized for any purpose
Logits, softmax, and sampling Probabilistic distribution and potentially nondeterministic selection Uncertainty, repeatability, and risk-appropriate output High probability does not constitute truth, compliance, or permission

This separation is especially important because partial interpretability does not eliminate the need for external controls. Attention weights, intermediate states, generated explanations, and chains of reasoning can provide useful signals, but none independently demonstrates the complete cause of a decision, the legitimacy of an action, or the future stability of behavior. The public SGAEIA formulation treats this limitation as a supervision problem: the less confidence there is in understanding the internal process, the less security can depend exclusively on that understanding and the more it must depend on bounded authority, mediated execution, revocation, and recovery (Silva, 2026d).

Observability must also be distinguished from evidence. Recording a prompt and response helps reconstruct part of an interaction, but it is insufficient to establish which identity initiated the operation, which policy was in force, what authority permitted a tool, what delegations occurred, and what effect was actually observed. In distributed or multi-agent systems, traces and spans help reconstruct trajectories, while evaluation and governed evidence answer different questions about outcome, legitimacy, and assurance. This relationship among tracing, evaluation, and evidence is examined in SGAEIA’s public research on agent execution (Silva, 2026e).

The connection to SGAEIA does not turn the article’s didactic examples into architectural controls. The table organizes high-level research questions and public properties while preserving the boundary between explanation and private mechanism. The operational conclusion is limited but important: understanding how an LLM produces a token is necessary to govern an LLM-based system, but it is not sufficient to authorize, observe, contain, or assure that system’s effects.

16. Conclusion

Opening the black box of inference makes it possible to follow the transformation of text into IDs, vectors, attention relationships, contextual representations, logits, and probabilities. The reduced examples show the arithmetic of each stage and make explicit where learned weights, masks, normalization, nonlinearity, and the decoding rule enter the process. They also clarify the limit of the demonstration: didactic numbers explain the mechanism, but they do not measure a real model and do not independently support claims about reasoning, safety, or reliability.

The banco case study shows why a token representation does not remain static after context passes through the layers. At the same time, the caveats concerning attention maps, emergence, and hallucination prevent a mathematical explanation from being confused with complete causal transparency. Inference is probabilistic, contextual, and dependent on weights, configuration, and decoding strategy; its analysis must preserve those conditions rather than convert fluency into certainty.

For SGAEIA, the principal implication is the separation between inference and effect. The model may propose a path, but authority determines whether that path is reachable, and policies and evidence determine whether it can become a legitimate action. Opening the black box of an agentic system therefore requires explaining not only how the token was produced, but also who authorized each action, under what limits, with what records, and with what capacity for interruption, revocation, and recovery.

19.1 Numerical core of the didactic example

File: 01_nucleo_numerico_calc.py. Function. Defines the four tokens (“O”, “banco”, “estava”, “lotado”) with hand-selected four-dimensional embeddings; computes sinusoidal positional encoding and X = E + P; applies Q, K, and V projections (fixed matrices, d_k = 2), QKᵀ scores, division by √d_k, and bidirectional softmax; and repeats softmax with a causal mask. It then traverses the rest of the block—Wo projection, residual addition, LayerNorm, RMSNorm, an FFN with d_ff = 8 and random weights using seed 0, logits over five words, softmax with T = 0.5, 1, and 2, and sorting for top-p—and writes the results to toy.npz.

Supports. Values in Sections 4–6 and Figures 2 and 4. The FFN and output results produced here use the bidirectional chain and are not those cited in the text; Sections 7–11 use Program 19.2, which recomputes the chain with a causal mask.

19.3 BPE merges in a didactic corpus

File: 03_bpe_didatico.py. Function. Executes eight BPE steps over the corpus low (5), lower (2), newest (6), and widest (3), using </w> as the end-of-word marker. At each step it prints the merged pair, its frequency, the three most frequent pairs, and the resulting vocabulary. Ties are resolved by order of occurrence.

Supports. The merge table in Section 3.

import re, collections
vocab={"l o w </w>":5,"l o w e r </w>":2,"n e w e s t </w>":6,"w i d e s t </w>":3}
def stats(v):
    p=collections.Counter()
    for w,f in v.items():
        s=w.split()
        for a,b in zip(s,s[1:]): p[(a,b)]+=f
    return p
def merge(pair,v):
    out={}
    bg=re.escape(" ".join(pair)); pat=re.compile(r'(?<!\S)'+bg+r'(?!\S)')
    for w,f in v.items(): out[pat.sub("".join(pair),w)]=f
    return out
for i in range(8):
    p=stats(vocab); best=max(p,key=lambda k:(p[k],))
    top=p.most_common(3)
    print(i+1,best,p[best],top[:3]); vocab=merge(best,vocab); print("  ",vocab)

19.7 HTTP audit of bibliography links

File: 08_auditar_links.py. Function. Opens each URL from the CSV, records the HTTP status and final URL, extracts the page title, and compares it with the expected title, classifying the entry as OK or REVIEW. It requires the requests library and Internet access. It was tested only against a local server, not against the live sites.

Supports. The auditoria_links_resultado.csv file to be generated by the reader (Section 18).

#!/usr/bin/env python3
"""Audita os links da bibliografia: abre cada URL, registra o código HTTP, a URL final
e compara o <title> da página com o título esperado. Uso: python3 auditar_links.py
Requer: pip install requests. Saída: auditoria_links_resultado.csv"""
import csv, re, sys, time, difflib, html
import requests

H = {"User-Agent": "Mozilla/5.0 (auditoria-bibliografia; contato: ORCID 0009-0008-2411-6995)"}

def norm(t):
    return re.sub(r"[^a-z0-9 ]", "", html.unescape(t).lower())

def titulo(txt):
    m = re.search(r"<title[^>]*>(.*?)</title>", txt, re.S | re.I)
    return re.sub(r"\s+", " ", m.group(1)).strip() if m else ""

rows = list(csv.DictReader(open("links_bibliografia.csv", encoding="utf-8-sig")))
out = []
for r in rows:
    url, esp = r["url"], r["titulo_esperado"]
    try:
        resp = requests.get(url, headers=H, timeout=25, allow_redirects=True)
        t = titulo(resp.text) if "html" in resp.headers.get("content-type", "") else ""
        sim = difflib.SequenceMatcher(None, norm(esp), norm(t)).ratio() if t else 0.0
        contem = norm(esp)[:40] in norm(t) if t else False
        # PDFs não têm <title>: apenas o status é verificável automaticamente
        ok = resp.status_code == 200 and (contem or sim >= 0.6 or not t)
        res = [r["n"], r["autor"], url, resp.status_code, resp.url, t[:90], round(sim, 2),
               "OK" if ok else "REVISAR (conferir título manualmente)"]
    except Exception as e:
        res = [r["n"], r["autor"], url, "erro", "", str(e)[:90], 0, "REVISAR (falha de acesso)"]
    out.append(res); print(res[0], res[3], res[7], url)
    time.sleep(1.0)
with open("auditoria_links_resultado.csv", "w", newline="", encoding="utf-8-sig") as f:
    w = csv.writer(f)
    w.writerow(["n", "autor", "url", "http", "url_final", "titulo_da_pagina", "similaridade", "resultado"])
    w.writerows(out)
print("\nConcluído:", sum(1 for o in out if o[7] == "OK"), "OK de", len(out))
